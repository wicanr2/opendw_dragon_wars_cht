## 1. 執行摘要(BLUF)

**一句話定位**:opendw_remake 是一套「**可從建角玩到結局、戰鬥核心數值對拍原版、全繁中的高保真技術 demo**」,但它**缺整個 RPG 成長與經濟循環**(升級 / 技能效果 / 商店 / 招募 / 使用物品),所以玩家拿到的是「**原版的氛圍與骨架,不是原版的養成樂趣**」。

**整體還原度:約 45–50%**(玩家可感體驗加權,見 §2 推導)。

拆兩個數字看,避免誤導:
- **技術 / 引擎保真度**:約 75%——渲染逐像素對拍、VM 117/256 opcode 逐指令對拍、戰鬥三大公式 bytecode 真值、存讀檔 byte-for-byte。這層是專案最硬的資產。
- **玩家可玩內容還原度**:約 35–40%——能走完一條「建角→探索 38/40 區→主線繁中事件→終戰→結局」的線,但這條線上**沒有變強的回饋迴圈**:打贏只加 80 XP 卻不會升級,撿到金幣沒處花,技能存了數值卻不檢定。原版 CRPG 的核心循環(探索→戰鬥→變強→買裝備→挑戰更難的區)在 remake 裡**只有「探索」和「戰鬥動作」兩環接通,「變強」與「經濟」整段缺席**。

**給決策者的一句話**:現在交出去,是一個**會讓人驚艷「居然能逐像素重現又全繁中通關」的 demo**,但**只要玩家玩超過 30 分鐘、期待「角色養成」,就會發現它是空心的**。下一步的最高產品槓桿不是補連通、也不是攻戰鬥真值,而是 **補上 RPG 成長迴圈(升級 + 使用物品 + 商店 + 招募)**,讓既有的探索與戰鬥「有意義」(理由見 §5)。

### 2.1 量化:玩家從頭玩到尾能體驗幾成原版?

**約 35–40% 的「可玩內容」**。推導(以原版玩家體驗時數權重估):

| 體驗構面 | 原版佔比(估) | remake 達成 | 加權 |
|---|:---:|:---:|:---:|

| 角色養成(升級/技能/配點) | 20% | ~12% | 2.4% |

| 劇情 / quest 驅動 | 15% | 40% | 6.0% |
| 招募 / 隊伍構築 | 5% | 0% | 0.0% |
| **合計** | 100% | | **~40%** |

### 2.2 哪些「原版核心樂趣」缺席(PM 重點)

CRPG 的樂趣公式 = **探索的未知 × 戰鬥的策略 × 成長的正回饋 × 構築的選擇**。remake 目前:

- ✅ **探索的未知**:在(高保真迷宮 + 自動地圖)。
- 🟡 **戰鬥的策略**:半在(基礎攻擊/法術在,特殊攻擊/閃避/遠程缺,策略維度被砍掉一半)。
- ⛔ **成長的正回饋**:**幾乎全缺**(不升級、技能不檢定)——這是最傷的一刀,玩家投入時間得不到「變強」的獎勵。
- ⛔ **構築的選擇**:**全缺**(不能招募、不能買裝、不能配點、不能換裝)——玩家無法表達「我想怎麼玩」。

**結論**:remake 留住了「看世界」的樂趣,丟掉了「養角色」的樂趣。對 CRPG 而言,後者通常是黏著度來源。

## 3. 品質 / 保真分層

把 remake 已落地的內容按「離原版真值多遠」分三層,評估對「忠實重製」這個產品定位的影響:

| 層 | 佔比(估,以已落地系統權重) | 內容 | 對「忠實重製」定位的影響 |
|---|:---:|---|---|
| **bytecode 真值**(逐指令/byte 對拍 opendw) | **~40%** | 渲染(viewport/sprite/scene/minimap 154 case)、VM 117 opcode 逐指令、戰鬥命中/徒手/武器骰、存讀檔、道具 23B 格式、gate 旗標機制 | **這是定位的底氣**。可機械化驗證、可對外宣稱「逐位元忠實」。是專案最值錢的資產 |
| **remake 設計 / grounded**(乾淨室,手冊背書) | **~45%** | 戰鬥閉環(combat_loop)、法術結算模型、結局序列、Namtar 屬性/祝福、連通 wrap 慣例、chargen 起始值、quest 進度推進 | **誠實標示下可接受**,但**不能宣稱是原版真值**。對「忠實」是稀釋——玩家以為在玩原版機制,實則玩 remake 的合理重建 |
| **受阻 / 暫定**(oracle 或架構所阻) | **~15%** | 跨區 edge→area 對映、戰鬥 HP 真值閉環、武器 STR bonus、怪物屬性、20 個 opendw NULL opcode、物品 gate set 來源 | **是「忠實」宣稱的風險點**(見 §4)。多數已誠實記錄,但對外溝通需謹慎 |

**對定位的判斷**:專案目前對「忠實重製」的處理**方法論上是健康的**(四級分明、不謊稱 oracle、卡點精確記錄)。風險不在「做假」,而在**「remake 設計」層佔比已接近一半**——一旦對外溝通簡化成「忠實重現原版」,容易讓受眾誤以為 45% 的 remake 設計也是原版真值。**建議對外一律用「高保真重製,核心引擎逐位元對拍,成長/結局為 grounded 重建」這種帶限定詞的措辭**。

## 5. 下一步建議(PM 排序)

|---|:---:|:---:|:---:|---|:---:|
| **A. 補 RPG 成長迴圈**(升級觸發 + 技能檢定 + X 配點 + 使用物品 U + 裝備穿脫) | **極高** | **M–L** | 低(無硬阻,數值層已備) | 讓既有戰鬥/探索「有意義」,補上最大空洞 | ⭐ **先做** |

### 我的明確推薦

**下一步做 A(補 RPG 成長迴圈),並立刻順手做 E 的 R8(清 README 漂移)。**

**理由(Y)**:
1. **最大產品槓桿在「成長」而非「連通/戰鬥真值」**。專案已能通關、戰鬥數字也對,但 §2.2 顯示玩家流失點是「打怪不會變強、撿錢沒處花、技能是死數字」。**A 把已經做好的探索與戰鬥從『能動』變成『有意義』**——這是 ROI 最高的一塊,因為它讓前面所有高保真投資(渲染對拍、戰鬥公式真值)真正轉化成玩家會留下來的體驗。
2. **A 無技術硬阻、數值層已就緒**(party/chargen/equipment/skills 欄位都解析好了,缺的是「動詞」與升等門檻/技能檢定的逆向),工時量級 M–L 可控,風險低。對比之下 **C(戰鬥真值閉環)是 L–XL 且受 oracle 阻,玩家可感價值卻只是「數字更精確」**——投入產出比明顯劣於 A。
3. **E 的 R8 幾乎零成本、立即修復對外可信度**(同一份 README 不該既寫 22/22 又寫 56/256)。在做 A 的同時清掉,避免「能通關的好專案被過時 README 拖累觀感」。

**第二優先 B(經濟+招募)**,與 A 合併後 remake 就具備完整 CRPG 循環(探索→戰鬥→升級→買裝→招募→挑戰),屆時「可玩內容還原度」可從 ~40% 拉到約 65–70%。**C 留到最後**:它是「忠實度」的潔癖項,風險高、玩家感知低,不該排在「讓遊戲好玩」之前。**D 內容工建議與 A/B 並行**(可由不同人/不同 session 推進,互不阻塞)。
